## Summary

Child content screens write session records to the `sessions` table when content is opened and closed. The parent dashboard fetches today's sessions on load (FR-010), then subscribes to live Postgres CDC inserts and updates for real-time visibility within 10 seconds (SC-001, FR-004). A daily summary is computed client-side from elapsed seconds grouped by activity type (US3). The `sessions` table already exists; this spec adds `family_id`, updates RLS policies, and adds the table to the Supabase Realtime publication.

## Implementation Notes

### Session Write Flow (Child)

```
Content screen mounts (e.g., game/[id].tsx)
  → useSessionWriter({ child_id, family_id, activity_type, content_item_id })
  → openSession():
      1. await recoverAbandonedSessions(child_id) if not already called this launch
      2. SELECT existing active session → close if found (FR-009)
      3. INSERT new session row → get sessionId
      4. On INSERT fail → queue to AsyncStorage
  → [user plays content]
  → screen unmounts (or app backgrounded)
  → closeSession(elapsed):
      1. clamp elapsed = Math.max(0, elapsed)
      2. UPDATE sessions SET ended_at, elapsed_seconds=clamped, status='completed'
```

### Parent Dashboard Load Flow

```
app/(parent)/index.tsx mounts
  → useTodaysSessions(childId, familyId, tzOffsetMinutes)
  → Phase 1: SELECT sessions WHERE child_id=childId AND today(tzOffset)
             → sessions[] state set
             → summary computed
  → Phase 2: subscribe postgres_changes INSERT+UPDATE on sessions WHERE family_id=eq.familyId
             → on INSERT: append to sessions[]
             → on UPDATE: replace row in sessions[] (captures ended_at)
  → Render:
      - "Recent Activity" list (FR-005): map sessions[] → ActivityItem components
      - Daily total (FR-006): summary.totalSeconds / 60 minutes
      - Per-type breakdown (US3)
```

### Timezone-Aware "Today" Query

```typescript
function todayBoundaryUTC(tzOffsetMinutes: number): { start: string; end: string } {
  const now = new Date();
  // Adjust now to local time by adding the offset
  const localMidnight = new Date(now);
  localMidnight.setUTCHours(0, 0, 0, 0);
  // Shift back to UTC using the offset
  const startUTC = new Date(localMidnight.getTime() - tzOffsetMinutes * 60_000);
  const endUTC   = new Date(startUTC.getTime() + 24 * 60 * 60_000);
  return { start: startUTC.toISOString(), end: endUTC.toISOString() };
}
```

## Key Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Schema update strategy | Additive migration (add `family_id`) | No destructive renames; existing code unchanged |
| Session write trigger | Content screen mount/unmount hooks | Screens know their own activity type; minimal coupling |
| Parent load strategy | Fetch + subscribe (two-phase) | Ensures no sessions missed before parent opened dashboard |
| Abandoned recovery | `elapsed_seconds=0`, `status='expired'` | Honest zero; session preserved for parent visibility |
| Duration calculation | Client-side clamp `Math.max(0, elapsed)` | Prevents negative values from clock skew |
| Daily summary | Client-side sum | YAGNI — no server aggregation needed for single child |
| CDC filter | `family_id=eq.${familyId}` | Matches RLS grain; efficient filtering |
