# Implementation Plan: Content Schema & Storage Setup

**Branch**: `009-content-schema-storage` | **Date**: 2026-06-10 (replanned 2026-06-10 post-clarify) | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/009-content-schema-storage/spec.md`

---

## Summary

Augment the existing `content_items` table with nullable type-specific columns (`content_text`, `assets_url`, `game_type`, `config_json`, `duration_seconds`) and create a new `categories` lookup table. Create four Supabase Storage buckets (`thumbnails`, `story-images`, `activity-assets`, `game-assets`). Extend TypeScript types and add new API hooks to expose the new fields — all without breaking any existing hooks or components.

---

## Technical Context

**Language/Version**: TypeScript 5.x (React Native / Expo project)

**Primary Dependencies**: Supabase JS v2 (`@supabase/supabase-js`), Expo SDK, React Native

**Storage**: PostgreSQL (Supabase) — single `content_items` table with type discriminator; new `categories` table

**Testing**: Jest + React Native Testing Library; integration tests target real Supabase (no mocks for DB tests)

**Target Platform**: iOS + Android (React Native); Supabase backend

**Project Type**: Mobile app + Supabase backend

**Performance Goals**: Age-group filtered queries return in < 1 second for up to 500 content rows (SC-002)

**Constraints**: No breakage to existing `useVideos`, `useStories`, `useGames`, `useCreative` hooks; RLS mandatory per constitution

**Scale/Scope**: 500–2000 content rows at launch; 4 content types; 4 storage buckets

## Phases

### Phase 1 — Schema Migration (US1, P1)

Goal: Apply the `content_items` column additions and `categories` table creation.

**Tasks**:
1. Create `supabase/migrations/` directory
2. Write migration SQL (`20260610000001_content_schema_v1.sql`) using the contract in `contracts/content-schema.sql`
3. Apply migration via Supabase Dashboard → SQL Editor (no Supabase CLI configured)
4. Verify new columns: `SELECT column_name FROM information_schema.columns WHERE table_name = 'content_items' AND column_name IN ('duration_seconds','content_text','assets_url','game_type','config_json')`
5. Verify RLS enabled (FR-011, FR-012): `SELECT tablename, rowsecurity FROM pg_tables WHERE tablename IN ('content_items', 'categories')`
6. Verify RLS policies: `SELECT policyname, tablename, cmd FROM pg_policies WHERE tablename IN ('content_items', 'categories')`

### Phase 2 — TypeScript Types (US1)

Goal: Add per-type interfaces that extend `ContentItem` without breaking existing code.

**Tasks**:
1. Edit `services/api/types.ts` — add `VideoItem`, `StoryItem`, `ActivityItem`, `GameItem`, `Category` interfaces
2. Add `ContentItemExtended` union type
3. Run `npx tsc --noEmit` — must be zero errors

### Phase 3 — API Hooks (US1)

Goal: Expose new columns via new hook functions alongside existing hooks.

**Tasks**:
1. Add `selectExtendedColumns` constant to `contentHelpers.ts`
2. Add `useVideoExtended()` to `videos.ts`
3. Add `useStoryExtended()` to `stories.ts`
4. Add `useGameExtended()` to `games.ts`
5. Create `services/api/categories.ts` with `useCategories()` hook
6. Run TypeScript check — zero errors

### Phase 4 — Storage Buckets (US2, P2)

Goal: Create four Supabase Storage buckets with public read access.

**Tasks**:
1. Create `thumbnails` bucket (public: true)
2. Create `story-images` bucket (public: true)
3. Create `activity-assets` bucket (public: true)
4. Create `game-assets` bucket (public: true)
5. Verify: upload test PNG to each bucket, confirm public URL resolves

### Phase 5 — Integration Tests (US1 + US2)

Goal: Contract tests verify that DB schema matches TypeScript types and buckets are accessible.

**Tasks**:
1. Write `tests/integration/contentSchema.test.ts`
   - Test: INSERT + SELECT round-trip for each content type with all new columns
   - Test: `categories` INSERT + SELECT
   - Test: age-group filter returns correct rows only
   - Test: category filter returns correct rows only
2. Run integration tests — all pass

### Phase 6 — Documentation & package.json scripts

**Tasks**:
1. Add `test:content-schema` script to `package.json`
2. Update `quickstart.md` with actual bucket URLs (post-creation)
3. Verify full test suite passes: `npm run test`
