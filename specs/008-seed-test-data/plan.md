# Implementation Plan: Seed & Test Data

**Branch**: `008-seed-test-data` | **Date**: 2026-06-09 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/008-seed-test-data/spec.md`

## Summary

The `daily_stats` seed file (`server/seeds/002_reports_seed.sql`) already exists and generates 30 days of randomised, idempotent usage statistics for up to 5 seed child profiles. What remains is constitutional compliance: adding an npm `seed:reports` CLI script (Constitution III), creating a `scripts/seed-verify.ts` verification script and its `package.json` entry, and adding a jest integration test (`tests/integration/seedVerify.test.ts`) that validates the verification logic (Constitution I + IV).

**Language/Version**: TypeScript 5.9 / React Native 0.83.6 (Expo SDK 55); PostgreSQL (Supabase)

**Primary Dependencies**:
- `@supabase/supabase-js` v2 — used in `seed-verify.ts` to query row counts
- `supabase` CLI — used to apply the SQL seed file
- `jest` — integration test for verification logic
- `ts-node` — runs `scripts/seed-verify.ts`

**Storage**: Supabase PostgreSQL — `daily_stats` table (written), `profiles` table (read-only)

**Testing**: `jest` unit + integration; `npm run test` for verification test

**Target Platform**: Supabase cloud (any tier); local Supabase (`supabase start`) for offline dev

**Project Type**: Developer tool / database seed (internal — no external API surface)

**Performance Goals**: Seed completes in < 60 seconds; verification script returns in < 5 seconds

**Constraints**:
- Manual execution only in production environments (FR-010)
- Idempotent: `ON CONFLICT (child_id, stat_date) DO NOTHING`
- Depends on `001_initial_data.sql` and `003_reports_tables.sql` being applied first
- Max 5 seed children (`LIMIT 5` in seed query)

**Scale/Scope**: Up to 150 rows (5 children × 30 days); one SQL file + one TS script + one test file

## Phase 2: Verification Script + Integration Test (Constitution I + IV)

### New File: `scripts/seed-verify.ts`

Connects to Supabase using the existing `services/api/client.ts` singleton. Runs three queries:

1. **Row count per child**: `SELECT child_id, COUNT(*) FROM daily_stats GROUP BY child_id`
2. **Category floor check**: `SELECT MIN(stories_seconds), MIN(games_seconds), MIN(videos_seconds), MIN(creative_seconds) FROM daily_stats`
3. **Finalization flags**: `SELECT is_finalized, COUNT(*) FROM daily_stats GROUP BY is_finalized`

Emits human-readable stdout (passes) and exits with code 1 if any check fails (for CI integration).

**SC verification mapping**:
| SC | Check |
|----|-------|
| SC-001 | Row count ≥ 1 per child (chart has data to render) |
| SC-002 | Script exits in < 5 s |
| SC-003 | Running seed twice → row count unchanged (idempotency; verified by running seed twice in CI) |
| SC-004 | All MIN() category values > 0 |

### New File: `tests/integration/seedVerify.test.ts`

Mocks `@supabase/supabase-js` following the pattern in `tests/integration/clockBypass.test.ts`. Tests:

1. **All rows present**: Mock returns 30 rows per child → verify passes
2. **Zero rows**: Mock returns 0 rows → verify reports failure + exits code 1
3. **Zero category value**: Mock returns rows with `min_stories = 0` → verify reports failure
4. **Finalization flags correct**: Mock returns all `is_finalized = true` for past dates → verify passes
5. **Today not finalized**: Mock returns today row with `is_finalized = false` → verify passes
