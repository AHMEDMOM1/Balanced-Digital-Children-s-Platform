# Implementation Plan: Push Notifications — Background Alerts

**Input**: Feature specification from `specs/021-push-notifications-background-alerts/spec.md`

---

## Summary

When child activity events fire (screen time limit reached, blocked content attempted, session ended), the child app writes a row to a new `notification_triggers` table. A Supabase Edge Function (`dispatch-notification`) is triggered by a Database Webhook on that table's INSERT event. The Edge Function fetches the parent's Expo push token from `device_registrations`, applies de-duplication and suppression rules, calls the Expo Push API, and records every outcome in `notification_events`. The parent app registers its token after login and suppresses visual alerts when in the foreground via `setNotificationHandler`. Two new DB tables, one column addition to `profiles`, and one Edge Function are required; all client calls are encapsulated in `services/api/notifications.ts`.

## Technical Context

**Language/Version**: TypeScript 5.x, React Native (Expo SDK 51), Deno (Edge Functions)

**Primary Dependencies**:
- `expo-notifications` — push token retrieval, permission requests, foreground handler
- `@supabase/supabase-js` v2 — DB reads/writes for triggers, events, tokens
- Supabase Edge Functions (Deno) — server-side `dispatch-notification` function
- Expo Push Notifications API (`https://exp.host/--/api/v2/push/send`) — delivery

**Storage**: Supabase PostgreSQL — new tables `notification_triggers` + `notification_events`; `profiles.notification_session_end_enabled` column; existing `device_registrations.device_token`

**Testing**: Jest + ts-jest; integration tests in `tests/integration/notifications.test.ts`; unit test for `computeNotificationText` (no network needed)

**Target Platform**: iOS + Android (React Native, Expo managed workflow); Edge Function on Supabase Deno runtime

**Performance Goals**: SC-001 — notification arrives within 60 seconds of trigger event; SC-006 — event recorded within 5 seconds of trigger INSERT

**Constraints**:
- RLS required on both new tables (Constitution §Row-Level Security)
- All client DB calls via `services/api/notifications.ts` — no direct `supabase.from()` in components (Constitution §API Hook Pattern)
- TDD: unit test for `computeNotificationText` written and RED before implementation (Constitution §I)
- `expo-notifications` must be installed via `npx expo install expo-notifications`

**Scale/Scope**: One parent device per family (v1); one child per family (current MVP)
