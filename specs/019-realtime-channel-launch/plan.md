# Implementation Plan: Realtime Channel Launch (Phase 4)

**Branch**: `019-realtime-channel-launch` | **Date**: 2026-06-13 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/019-realtime-channel-launch/spec.md`

## Summary

Phase 4 completes the real-time communication layer between parent and child devices. The channel infrastructure (`subscribeFamilyChannel`, `RealtimeProvider`, `commandProcessor`) already exists and is wired into both device layouts. This spec fills five concrete gaps: (1) adds `settings_sync` command type, (2) extends `HeartbeatEvent` with activity data, (3) adds Postgres CDC settings-change delivery to the child, (4) stores heartbeat details in the parent's realtime store for dashboard display, and (5) adds integration tests for all channel scenarios.

## Technical Context

**Language/Version**: TypeScript 5 / React Native (Expo SDK 52)

**Primary Dependencies**: `@supabase/supabase-js` (Realtime broadcast + Postgres CDC), Zustand, expo-router

**Storage**: Supabase PostgreSQL — `realtime_commands`, `profiles`, `category_preferences` (existing tables, no schema changes)

**Testing**: Jest + real Supabase instance (service-role + anon-key pattern from spec 018)

**Target Platform**: iOS + Android (Expo Go / bare workflow)

**Performance Goals**: Commands delivered ≤ 2s; settings changes applied ≤ 10s; reconnect ≤ 5s

**Constraints**: No new native modules; must work offline (CDC + command queue); single-channel per family

**Scale/Scope**: 1 parent + 1 child per family (multi-child deferred)

## Implementation Phases

### Phase 1: Type Extensions (prerequisite for all other changes)

Extends `services/realtime/types.ts` with `settings_sync` command type, extended `HeartbeatEvent`, and `SettingsSyncPayload`. These are additive-only changes — no existing consumers break.

### Phase 2: TDD Red — Write Integration Tests

Write `tests/integration/realtimeChannel.test.ts` with all 8 scenarios (A–H). All scenarios will fail (RED) because the production code changes in Phase 3 have not been made yet.

### Phase 3: Implement Channel Enhancements (Green)

Execute these changes in order:

1. **`commandProcessor.ts`** — add `settings_sync` case that calls `useSettingsStore.setState()` with the payload fields
2. **`useRealtimeStore.ts`** — add `latestHeartbeat: HeartbeatEvent | null` and `setLatestHeartbeat(hb: HeartbeatEvent)`
3. **`useSessionStore.ts`** — add `currentActivity: ActivityType | null` and `currentContentId: string | null` with setters
4. **`familyChannel.ts`** — add `subscribeSettingsChanges(childId, familyId, handlers)` function
5. **`RealtimeProvider.tsx`** — four targeted edits:
   - `onHeartbeat`: store full event via `setLatestHeartbeat`
   - `heartbeatIntervalRef`: include `current_activity` and `current_content_id` from session store
   - Child role: call `subscribeSettingsChanges` in `useEffect`, clean up in return
   - Import `subscribeSettingsChanges` from familyChannel
6. **`app/(parent)/index.tsx`** — display child status (online/offline, activity, elapsed time) from `latestHeartbeat`

### Phase 4: Validation

Run full test suite. Verify all 8 scenarios pass. TypeScript check (`npx tsc --noEmit`).

### `services/realtime/familyChannel.ts`

New exported function:
```typescript
export interface SettingsChangeHandlers {
  onProfileUpdate: (fields: Partial<{ daily_limit_minutes: number }>) => void;
  onCategoryUpdate: (category: string, isAllowed: boolean) => void;
}

export function subscribeSettingsChanges(
  childId: string,
  familyId: string,
  handlers: SettingsChangeHandlers
): () => void {
  const channel = getClient()
    .channel(`settings-sync:${childId}`)
    .on('postgres_changes', 
      { event: 'UPDATE', schema: 'public', table: 'profiles', filter: `id=eq.${childId}` },
      (payload) => {
        const row = payload.new as any;
        handlers.onProfileUpdate({ daily_limit_minutes: row.daily_limit_minutes });
        console.debug('[settings-sync] profile update', { childId });
      }
    )
    .on('postgres_changes', 
      { event: '*', schema: 'public', table: 'category_preferences', filter: `family_id=eq.${familyId}` },
      (payload) => {
        const row = (payload.new ?? payload.old) as any;
        if (row?.category && typeof row.is_allowed === 'boolean') {
          handlers.onCategoryUpdate(row.category, row.is_allowed);
          console.debug('[settings-sync] category update', { category: row.category });
        }
      }
    )
    .subscribe();
  return () => { getClient().removeChannel(channel); };
}
```

    },
  });
}
